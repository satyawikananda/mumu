# Mumu website

Astro landing-page workspace for Mumu TV. This setup provides the tooling and motion foundation; the current page remains the Astro starter.

## Stack

- Astro 7 with strict TypeScript and Bun for package management.
- Tailwind CSS 4 through `@tailwindcss/vite`; global styles live in `src/styles/global.css`.
- `@lucide/astro` for icons rendered as inline SVG without client hydration.
- GSAP and ScrollTrigger, synchronized with Lenis through one GSAP ticker.
- ESLint flat configuration using `@antfu/eslint-config`, with Astro support enabled.
- `@astrojs/cloudflare` and Wrangler for Cloudflare Workers. Pages are prerendered by default; sessions are disabled. Images are optimized at build time.

## Local development

Use Node.js 22.23.4 or later and Bun. From this directory:

```sh
bun install --frozen-lockfile
bun run dev --background
```

Manage the development server with `bun run astro dev status`, `bun run astro dev logs`, and `bun run astro dev stop`.

```sh
bun run lint
bun run lint:fix
bun run check
bun run build
bun run preview
```

The recommended VS Code extensions include Astro, ESLint, and Tailwind CSS. Saving a file applies ESLint fixes.

## Icons and motion

Import only the icons a component uses:

```astro
---
import { ArrowUpRight } from '@lucide/astro'
---

<a href="https://github.com/satyawikananda/mumu" class="inline-flex items-center gap-2">
  View source
  <ArrowUpRight size={18} aria-hidden="true" />
</a>
```

`src/layouts/Layout.astro` imports global styles and the browser-only motion entrypoint. Add `data-reveal` to an element to opt into a short scroll reveal. Content stays visible when JavaScript is unavailable. Lenis and reveals run only when `prefers-reduced-motion: no-preference` matches, including changes to that preference at runtime. Touch scrolling retains Lenis's native defaults.

The motion entrypoint removes its ticker callback and destroys Lenis during cleanup. GSAP reverts scoped animations and ScrollTriggers. Astro navigation events, browser back/forward cache restoration, and hot module replacement are handled. Import GSAP in component scripts for future micro-interactions; register their cleanup with the same component lifecycle.

## Cloudflare Workers

The deployment target is `mumu-website`, configured in `wrangler.jsonc`. Run:

```sh
bun run cf:types
bun run deploy:check
```

The dry run builds and validates deployment packaging without publishing. After configuring the intended Cloudflare account and authenticating locally, deploy with:

```sh
bun run deploy
```

For Cloudflare Workers Builds, use `website` as the project root, `bun install --frozen-lockfile` as the install command, `bun run build` as the build command, and `bunx wrangler deploy` as the deploy command. Wrangler uses the deployment configuration generated by the Astro adapter. Generated build output and runtime types are ignored by Git.

Set Astro's `site` option once the public domain is known. No account ID, custom domain, or credentials are included in this workspace.

Wrangler is used because the current `cf` beta does not support building Astro 6 and later. See the [Cloudflare compatibility note](https://developers.cloudflare.com/cf/get-started/first-worker/#start-from-an-existing-project) and [Astro Cloudflare adapter documentation](https://docs.astro.build/en/guides/integrations-guide/cloudflare/).
